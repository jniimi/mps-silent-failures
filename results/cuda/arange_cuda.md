# CUDA の torch.arange(int64, N > 2**32) 検証 (2026-09-19, Colab A100-SXM4-80GB)

N = 2**32 + 2**20。`x = torch.arange(N, dtype=torch.int64, device=dev)`。

| torch | device | x[2**32-1] | x[2**32] | x[-1] |
|---|---|---|---|---|
| 2.11.0+cu128 | cuda | 4294967295 | 0 | 0 |
| 2.12.1+cu130 | cuda | 4294967295 | 0 | 0 |
| 2.13.0+cu130 | cuda | 4294967295 | 0 | 0 |
| 2.14.0+cu130 | cuda | 4294967295 | 0 | 0 |
| 2.11.0 | cpu (Mac Studio) | 4294967295 | 4294967296 | 4296015871 |
| 2.14.0 | cpu (Mac Studio) | 4294967295 | 4294967296 | 4296015871 |

- CUDA では先頭 2**32 要素は正しく、それより後ろの 2**20 要素はすべて 0(2.11.0 で数えて非ゼロ 0 件)。エラーなし
- N = 2**32 + 5 でも末尾 5 要素が 0。N = 2**31 + 5 は正しい
- 同じ長さの `torch.empty(N).fill_(7)` は末尾まで正しいので、読み出し側ではなく arange の書き込みの問題
- MPS (torch 2.14.0) は壊れ方が違う: 先頭の N mod 2**32 要素だけが正しく、残りが 0
